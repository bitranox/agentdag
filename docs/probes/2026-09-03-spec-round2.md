# Probe: agentdag on `agentswarm`'s `spec` case, round 2

Round 1 is VOID for three reasons, recorded in `2026-09-03-spec-round1.md`. This round is what
its third reason forces: the sonnet control SATURATED the case at 81/81 with a third of the token
ceiling unspent, so score cannot separate a competent coordinator from a competent single agent
here. The measured quantity changes rather than the case.

Run under `agentswarm/docs/evaluation-protocol.md`, reported in the form
`agentswarm/docs/agentdag-comparison-handover.md` specifies.

**Everything above the divider was written before the run started and is not edited afterwards.**

## Pre-registration

### What is being compared, and why there are three arms

| Arm | System                                         | Model row                                      |
|-----|------------------------------------------------|------------------------------------------------|
| P   | agentdag `plan-goal`, policy pinned to one row | sonnet everywhere                              |
| S   | agentdag `plan-goal`, shipped policy           | whatever the planner's `tier_role` resolves to |
| C   | one Claude agent in one context                | sonnet                                         |

P against C isolates DECOMPOSITION, which is the thesis: the only difference is the coordinator.
S against P prices what the tier policy buys, which is a separate question and was fused with the
first one in round 1. Round 1's held-fixed table claimed a single worker tier and agentdag ran
fable, sonnet and opus, so the two effects could not be told apart; splitting them is why this
round has three arms and not two.

### What is measured

**New tokens and wall clock at the FIRST crossing of 81/81**, not the score at the ceiling. An arm
stops the moment it saturates, so no arm is expected to reach either ceiling.

An arm that never crosses reports its score at its stop instead, and the round says so per arm
rather than rendering a non-crossing as a large cost. An absent measurement must not appear in the
same column as a measured one.

### Held fixed

| Setting            | Value                                                              |
|--------------------|--------------------------------------------------------------------|
| case               | `spec`, agentswarm commit `071f36c`, `max_score` 81                |
| visible gate       | `pytest tests/ -q` - 92 seeded tests, green on the untouched stubs |
| new-token ceiling  | 1,200,000, shared by all three arms                                |
| wall-clock ceiling | 2400 s, shared by all three arms                                   |
| task text          | one goal string, byte-identical across arms, step-0 copy included  |
| stop condition     | first crossing of 81/81; else whichever ceiling comes first        |
| runs per arm       | 1                                                                  |

The model row is deliberately NOT in this table. It is the axis P and S vary, and writing it here
is what made round 1's table false.

### The instrument, and what must be true before any number counts

Each runner scores the workspace with `cases.score` at its own checkpoints - after each prompt for
arm C, after each node lands for P and S - and records the tokens and elapsed time at the first
result reading 81/81.

**Two validity requirements, pre-registered so a bad instrument cannot be read as a result.**

1. The checkpoint scorer must be shown to DISCRIMINATE before the arms run: scored against the
   untouched seed it must read 0/81, and against `hidden/reference` it must read 81/81. A scorer
   that cannot tell those apart cannot detect a crossing, and a constant reading is a broken
   instrument rather than agreement.
2. A checkpoint that catches a half-written tree reads low, so only an upward crossing counts and
   the first 81/81 is taken as the crossing. A single low reading after a high one is not a
   regression to report; two consecutive would indicate the scorer is racing the writer, and the
   run is VOID for that arm rather than reported.

Both runners already charge the protocol's unit - `input_tokens + cache_creation_input_tokens`,
keyed by dispatch or by message id, cache reads excluded and reported separately.

### Deviations, stated in advance

* **The workspace is copied in by the run itself**, for all three arms equally. `plan-goal` mints
  its own empty `wt/root` and takes only a goal string, so no arm is handed a pre-seeded
  directory; each is told to copy it as step 0.
* **Round 1's control is NOT carried forward.** It saturated, but its 760,578 tokens is the cost
  to its DEADLINE and not to its crossing: it kept working after reaching 81/81 and its workspace
  is not a repository, so no history exists to recover the crossing from. Arm C is re-run with the
  checkpoint instrument.
* **agentdag runs on the kernel from `c446771` or later.** Round 1's arm A died on a readiness
  defect fixed there, so this round's coordinator is not the one round 1 measured. That is a
  deliberate change of the system under test between rounds, which is why round 1 is void rather
  than a comparable baseline.
* **One run per arm**, so any difference smaller than the run-to-run spread of either is
  indicative and not a result.

### What each outcome band will mean

| Band                                            | Reading                                                                                                                         |
|-------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| no arm crosses 81/81                            | the ceiling is below this case's cost for every arm; the round reports scores and the cost-to-saturation question is unanswered |
| only C crosses                                  | the coordinator cannot finish what one agent can, which is the strongest available evidence against the thesis                  |
| P crosses at lower cost than C                  | the first real evidence for decomposition on this case - still one run, still indicative                                        |
| P crosses at higher cost than C                 | decomposition is not repaying its overhead where one agent can finish alone; says nothing about a task one agent cannot finish  |
| S cheaper than P                                | the tier policy pays for itself, and P is the crippled arm rather than the honest one                                           |
| S dearer than P at the same crossing            | the tier policy costs more than it buys on this case                                                                            |
| any arm's hidden suite ERRORS rather than fails | read the two apart: all-errored means the tree would not import, all-failed means the work was not done                         |

### Coordination metrics

A dash for every arm, never a zero. Undefined for a DAG in fixed order and for an agent with no
peers, and a system scores perfectly on all of them by doing nothing.
